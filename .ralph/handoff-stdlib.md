## 2. THE CURRENT BLOCKER (diagnosed, fix designed, not applied)

`list-ref` evals HANG (compile-time evaluation loops; the probe stalls
after the list-fold eval line). Root cause: ref-fn's fork arm puts the
recursion in an `if` ARGUMENT position:

    fork arm = λhd.λtl. ((if (%0 hd) (self (pred i) tl)) (is-zero i))

The compile evaluator (compiler/lib/bracket.ml `to_tagged`) is strict:
it reduces arguments BEFORE the branch is selected, so `(self (pred i) tl)`
fires even when i=0 — and `nat-pred 0 = 0`, so the countdown never
decrements → infinite compile loop (burns the 1e8 compile fuel = minutes).

**The fix** (same pattern the green defs use — recursion only under
arm lambdas, never in argument positions): dispatch on `i` itself with
tree-case, so each branch is an arm (selected-then-reduced):

    fork arm = λhd.λtl. dispatch i            # i = small nat
                        (%0 hd)               # i=0   → some hd
                        (λc. (self c tl))     # i=n+1 → recurse on pred
                        (λu.λv. %0)           # junk  → none

In gen_defs.py terms replace REF_FN's inner if with:
`dispatch("i", L("%0","hd"), lam("c", L("self","c","tl")), lam("u", lam("v","%0")))`
inside the hd/tl arm. Then re-run the probe; expect ref 0 → some %10
(`110`), ref 1 → some %200 (`1200`), ref 2 → `0`. NOTE: the OLD fold-based
list-ref was ORDER-SWAPPED (fold-right acc flows tail→head) — do not
resurrect it.

## 3. HARD-WON COMPILER FACTS (load-bearing — reread before writing any def)

1. **Compile IS reduction** (bracket.ml `to_tagged`): every CLOSED redex
   fires at compile time, fuel 1e8, args reduced before calls (strict,
   leftmost-innermost). Lambda params are the ONLY barrier — and bracket
   abstraction ELIMINATES them, so "openness" only exists pre-elimination.
2. **Self-application cannot survive**: `(C C)` is a closed redex and
   re-creates itself inside its own body → infinite compile loop or
   exponential size (both observed: fuel burn AND stack overflow in
   size_of). `(rec x)` binds rec to the DATA (wrong); `(rec rec ...)` in
   an arm body still fires (closed head). Do NOT use Y/me-recursion.
3. **The ONLY working recursion = the upstream fix machinery** (gen.ml
   `fix`, verbatim from reference test.mts): `sa-k`/`wait`/`wait1`/
   `rec-fix` (in gen_defs.py, all verified). Pattern: functional =
   `λself.λdata...` (DATA FIRST), recursion calls `self ...` (the
   functional's own param, threaded through the wait machinery), the
   consumer applies `(rec-fix F)` to data that is OPEN at compile time.
   The wait barriers stop the compile evaluator exactly one unfold per
   runtime data step. `nat-sum`, `fold-fn`, `eq-fn` all use this ✓.
4. **Eager arguments**: a recursion in an `if`/application ARGUMENT
   position fires before the branch selects (the list-ref bug). Put
   recursion in tree-case ARM bodies (selected-then-reduced) or under
   arm lambdas.
5. **Arg-order gate**: engines take the DATA argument FIRST so the
   consumer's application has an open head at compile time. list-fold is
   η-wrapped into consumer order (f z xs) over the engine's (xs f z).
6. **Our fold is fold-RIGHT** (acc = the folded TAIL, computed innermost):
   - `fold cons nil xs` = xs (identity, NOT reverse);
   - reverse must APPEND: `fold (λh.λacc. append acc [h]) nil xs`;
   - anything needing head-first statefulness (countdowns) must use
     rec-fix, not the fold.
7. **Reader facts**: def names must be var atoms `[-_a-zA-Z0-9]` (no `?`
   — hence is-leaf/is-stem/is-fork; the book's `leaf?` spelling needs the
   rename noted in the book at landing). `pair`/`cons` alias the LEAF:
   `(pair a b) = Fork(a,b)` at zero triage. `%ternary` literals: mind
   that they be VALID ternary (balanced). **succ = %0** (apply-Leaf
   wrapper), **some = %0** (Stem x = some x). Canon.of_string returns
   (int*string) errors. `tree-case` = upstream T{f0,f1,f2} — gen.ml
   `tcase`/TCase confirms the shape; no upstream typecase DEF exists, so
   ours is tuna-derived and PROPERTY-PINNED (the chapter mandates the
   result+steps table at make time — the table in §1 IS it).
7b. **Only the LEAF arm may be a bare value.** tree-case's leaf arm is
   returned plain, but stem/fork arms are APPLIED to the parts (stem gets
   the child, fork gets l then r). A bare application VALUE in a stem/
   fork slot gets that value applied to the child - observed: mag-cmp's
   eq verdict %10 applied to a stem child leaf produced %200 (i.e.
   apply(%10, leaf) = Fork(Leaf,Leaf)). Bare values are fine in the leaf
   slot (mag-ripple's (pair hd tl) green there); wrap stem/fork slots in
   a lambda absorbing the parts even when ignored.
8. **Probe gotchas**: dune runs tests from `_build/default/tests` etc.;
   `Tuna.Canon.of_string` error is a pair; tool dune stanzas need
   `(modules ...)`; deep recursion in the COMPILER overflows the OCaml
   stack (size_of) — that's F5's shape, not a timeout.
